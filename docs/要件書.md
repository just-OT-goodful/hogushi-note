# ほぐしノート（肩こり・腰痛セルフケアアプリ）要件定義書

最終更新：2026-11-01（Service Worker v7 時点）

## 1. 背景・目的

- 肩こり・腰痛は、セルフケアを「続けること」と「効果を実感すること」が改善の鍵になる一方、続けられない・変化が分からないという理由で途中でやめてしまう方が多い
- 整えサロンのお客様をはじめ、肩こり・腰痛でお悩みの方が、**自宅で無理なくセルフケアを続けられる**ようにするためのアプリとする
- 解決したいこと（機能の柱）
  1. 定期的に体を動かすよう、**リマインド**する
  2. ストレッチなどの自主トレのやり方を、**イラスト（動き）・手順で分かりやすく解説**する（写真・動画も追加できる）
  3. セルフケアをしたことを**見える化**する
  4. 肩こり・腰痛の程度の**変化を見える化**する
- 会員登録・ログインを不要とし、スマホのホーム画面に追加して、アプリのように使えるようにする（PWA）
- GitHub Pages で公開でき、サーバーや運用費用が不要な構成とする

## 2. 運営者情報・利用者

- 作業療法士が運営する健康増進サロン「整えサロン」の運営者が作成・配布する
- 主な利用者：肩こり・腰痛を有する方（サロンのお客様、運営者自身）。想定規模は小人数
- 利用環境：スマホ（iPhone Safari／Android Chrome）が中心。パソコンのブラウザでも見やすく表示する
- 運営者は利用者の記録を**預からない**（データは利用者の端末内のみ。個人情報・健康情報を運営者側で保管しない）

| 項目 | 内容 |

## 4. 画面構成

画面は「ホーム」「体操」「記録」「設定」の4つ。スマホは下部タブ、パソコン（幅960px以上）は左サイドバーで切り替える。

### 4.1 ホーム
- 挨拶・日付、今日のケア回数、連続日数、今週ケアした日（x/7）、直近7日のカレンダー表示
- 次のリマインド予定の表示（未設定時は設定画面への案内）
- **初回の説明カード**：記録は端末内のみに保存されること、消えうるケース、バックアップの案内、ホーム画面への追加の勧め（「わかりました」で非表示）
- **バックアップのお知らせ**（4.5章参照）
- 今日の状態（こり・痛みの最新記録）と記録ボタン
- **まとめてケア**：3つのルーティン（朝のリセット／デスクワークの合間／寝る前の腰ケア）。所要時間の目安と種目名を表示
- 受診をおすすめする目安（開閉式）、ホーム画面に追加する方法（未インストール時のみ）

### 4.2 体操（一覧・詳細）
- **一覧**：12種目をイラスト付きのカードで表示。「すべて／首・肩／腰・骨盤」で絞り込み（スマホ2列、タブレット3列、パソコン4〜5列）
- **詳細**
  - 人物イラストによる動きのアニメーション。**①はじめの形**と**②動かした形**を並べて表示し、タップでその形に固定、「▶ 動きを見る」で再生
  - 動かす向きの矢印、効かせたい場所の強調表示
  - 回数の目安、**キープタイマー**（秒数のカウントダウン、一時停止・再開、片側→反対側の案内、終了時に音と振動、計測中は画面を暗くしない）／**回数カウンター**
  - やり方（手順）、ポイント、注意、なぜ効くか（短い説明）
  - 「やった！記録する」で記録（二重タップで2回記録されない）
  - **写真・動画**：この端末内の写真・動画の追加、YouTube等の動画リンクの追加（同梱メディアも表示可能）
  - パソコンでは、左にイラスト（スクロール追従）・右に手順の2段組み

### 4.3 記録
- **こり・痛みの変化**：首・肩／腰を0〜10で記録。7日・30日・90日の折れ線グラフ（ケアの回数の棒グラフを併記）、直前の同期間との比較（改善傾向／悪化傾向の表示）、ケア直後の変化の平均
- **セルフケアの見える化**：期間内のケア回数・ケアした日数・連続日数、直近12週のカレンダー（ヒートマップ）、よく行った体操
- **最近の記録**：直近12件の履歴の確認と個別削除

### 4.4 設定
- **リマインド**：ON/OFF、通知の許可状況、時刻（複数・重複なし・昇順）、曜日、おすすめの設定（2時間おき／朝・昼・夕／朝・夜）、テスト通知
- **カレンダーに登録**：設定した時刻と曜日を、くり返し予定＋アラーム付きの `.ics` として保存
- **ホーム画面に追加**：手順の案内、対応ブラウザではインストールボタン
- **データのバックアップ**（4.5章）
- このアプリについて（診断・治療の代わりではない旨）

### 4.5 バックアップ
- **バックアップを保存・送る**：記録をJSONファイルにし、共有シートに対応する端末では共有画面（ファイルアプリ・メール・LINE等）を開く。非対応端末はファイルとして保存。共有画面を閉じただけの場合は「バックアップ済み」と扱わない
- **バックアップから復元する**：JSONを読み込む。**追加方式**（いまの記録は消えず、同じIDの記録は重複しない）。形式が不正な記録は除外し、除外件数を表示
- 設定画面に「最終バックアップ：年/月/日（◯日前）」を表示
- **ホームでの案内**：記録が5件以上あり、最後のバックアップから30日（未実施の場合は最古の記録から14日）たつと表示。「今すぐバックアップ」／「7日後に知らせる」
- ブラウザに永続ストレージ（消さないでほしい）を要求し、許可状況を設定画面に表示
- 自分で追加した写真・動画はバックアップに含まれない（画面にも明記）
- 「記録をすべて削除」（確認あり）

## 5. 体操・ルーティン

### 5.1 体操（12種目）
| 区分 | 体操 | 回数の目安 |
|---|---|---|
| 首・肩 | 首の横ストレッチ | 20秒キープ × 左右 × 2セット |
| 首・肩 | 肩甲骨寄せ | 10回（3秒キープ）× 2セット |
| 首・肩 | 肩まわし | 10回 × 2セット |
| 首・肩 | あご引き | 10回（3秒キープ） |
| 首・肩 | 胸のストレッチ | 20秒キープ × 3セット |
| 首・肩 | 肩すくめ脱力 | 8回（3秒キープ） |
| 腰・骨盤 | ひざ抱えストレッチ | 20秒キープ × 3セット |
| 腰・骨盤 | 骨盤ゆらし | 10回 |
| 腰・骨盤 | 背中丸め・反らし | 8回 |
| 腰・骨盤 | お尻のストレッチ（4の字） | 30秒キープ × 左右 |
| 腰・骨盤 | 太もも裏のストレッチ | 20秒キープ × 左右 × 2セット |
| 腰・骨盤 | お尻上げ（ブリッジ） | 10回（2秒キープ） |

各体操は、狙い（筋肉・部位）、実施場所（椅子／立つ／マット・布団）、手順、ポイント、注意、なぜ効くかを持つ。体操は `js/data.js` で追加・変更できる。

### 5.2 まとめてケア（ルーティン）
| 名前 | 種目 | 使う場面 |
|---|---|---|
| 朝のリセット | 骨盤ゆらし → ひざ抱え → 肩まわし → 肩甲骨寄せ → 首の横 | 起きてすぐ |
| デスクワークの合間 | 肩すくめ → あご引き → 首の横 → 肩甲骨寄せ → 太もも裏 | 座ったまま |
| 寝る前の腰ケア | ひざ抱え → 4の字 → 骨盤ゆらし → 背中丸め・反らし → ブリッジ | 就寝前 |

- 1種目ずつ案内し、「できた！ 次へ」で記録して進む。「とばす」「やめてホームへ」も可
- 完了画面から「ケア後の状態」を記録でき、ケアの前後の変化を集計に反映する

### 5.3 安全面の配慮
- 受診の目安（外傷後、しびれ・脱力、排尿・排便の異常、発熱、安静時・夜間の強い痛み、2週間以上変わらない／悪化）をホームに掲載
- 各体操に「痛みが強くなる場合は、すぐにやめる」旨と、体操ごとの注意を表示
- 診断・治療の代わりではないことを、ホーム・設定に明記

## 6. データ仕様

### 6.1 保存先
- 記録・設定：`localStorage`（キー `selfcare.v1`）
- 自分で追加した写真・動画：`IndexedDB`（`selfcare-media`）
- 外部サーバーへの送信は一切ない

### 6.2 主なデータ
| 項目 | 内容 |
|---|---|
| logs | セルフケアの記録：id、体操ID、日時 |
| checkins | こり・痛みの記録：id、日時、首・肩(0〜10)、腰(0〜10)、ひとこと(80字まで)、ケア後フラグ |
| remind | リマインド：ON/OFF、時刻の配列（HH:MM）、曜日の配列（0〜6） |
| links | 体操ごとの動画リンク（http/https のみ） |
| meta | 最終バックアップ日時、お知らせの保留期限、初回説明の表示済みフラグ |
| fired | 通知済みの記録（重複通知の防止） |

### 6.3 データの安全性
- 読み込み時（起動時・バックアップ復元時）にすべての項目を検証し、不正なデータ（数値が不正・範囲外・IDの重複・`javascript:` 等のリンク）を除外または補正する
- **複数の画面（ホーム画面アプリとブラウザのタブなど）を同時に開いても、記録を上書きして消さない**。更新の直前に保存済みの内容を読み直し、別の画面での変更は画面にも反映する
- 保存に失敗したとき（容量不足・プライベートモード等）は、画面で知らせる

### 6.4 データが消える可能性（利用者に案内する内容）
- ブラウザのデータ削除、ホーム画面アプリの削除、機種変更（端末間の同期はしない）
- iPhone では、Safari のタブとホーム画面のアプリで保存場所が別
- iPhone の Safari で、ホーム画面に追加せずに約7日間開かない場合
- プライベートモード
- 端末の空き容量が極端に少ない場合（まれ）
- → バックアップ機能（4.5章）と、初回説明・お知らせで備える

## 7. リマインド

- **アプリを開いている間**：設定した時刻（予定から30分以内）に、画面上部のバナー（「始める」でその時間帯のルーティンを開始）と、バックグラウンド時は端末の通知でお知らせする。同じ時刻は1日1回のみ
- **確実に知らせたいとき**：`.ics`（くり返し予定＋アラーム）をカレンダーに登録する。Webアプリの仕様上、アプリを閉じている間に決まった時刻で通知を出すことはできないため、この2本立てとする（画面にも明記）
- 時間帯とルーティンの対応：11時前＝朝、19時以降＝寝る前、それ以外＝デスクワーク

## 8. 非機能要件

### 8.1 PWA・オフライン
- `manifest.webmanifest` によりホーム画面に追加でき、全画面（standalone）で開く
- Service Worker により、アプリ本体をキャッシュしてオフラインでも開ける（キャッシュを先に返し、裏で最新を確認して更新。更新の反映は、公開後の1〜2回目の起動）
- 共有リンクの末尾（`?…`）が違っても、キャッシュが増え続けないよう保存先をそろえる
- 構成ファイルを増減したときは、`sw.js` の `ASSETS` と `VERSION` を更新する

### 8.2 画面・表示
- スマホ（〜959px）：下部タブ、1列。タブレット（700px〜）：本文幅を拡大。パソコン（960px〜）：左サイドバー、2列（列は固定で、開閉などで入れ替わらない）、本文は最大1120〜1280px
- ライト／ダークに対応（端末の設定に追従）
- 画面を切り替えるたびに、ページタイトルを更新し、本文にフォーカスを移す

### 8.3 アクセシビリティ
- 文字のコントラストは4.5:1以上（ライト・ダークとも確認済み）。グラフの線は色だけでなく線種・マーカー形状でも区別する
- すべての操作ボタンに名前を付け、キーボードで操作できる。入力シートはフォーカスを閉じ込め、Esc で閉じ、閉じると元の位置へフォーカスを戻す。シート表示中は背景をスクロールしない
- 動きを減らす設定（prefers-reduced-motion）では、アニメーションを自動再生しない
- 主要ボタンは高さ44px以上、絞り込み・曜日などの小さなボタンも40px以上

### 8.4 プライバシー・セキュリティ
- 個人情報・健康情報を外部へ送信・保管しない（サーバーなし）。利用者の記録を運営者は見られない
- 外部への通信は、利用者が追加した YouTube 動画の埋め込み（youtube-nocookie.com）のみ
- 入力文字は常にテキストとして表示し、HTMLとして解釈しない

### 8.5 対応環境
- iPhone（iOS 16.4以降のSafari／ホーム画面アプリ）、Android（Chrome）、パソコン（Chrome・Edge・Safari・Firefox の最新版）
- 通知は、ホーム画面に追加した状態（iOS）／通知を許可した状態で利用できる。非対応環境ではアプリ内のお知らせのみ

## 9. 技術構成

| 項目 | 内容 |
|---|---|
| 構成 | ビルド不要の静的PWA（HTML／CSS／素のJavaScript（ES Modules））。npm・Node.js は不要 |
| ホスティング | GitHub Pages（GitHub Actions） |
| 人物イラスト | 関節座標から描画するSVG（`js/figure.js`）。体操データは `js/data.js` |
| グラフ | ライブラリなし（SVG／DOM、`js/charts.js`） |
| ファイル構成 | `index.html`、`sw.js`、`manifest.webmanifest`、`css/`、`js/`（`app.js` `data.js` `store.js` `backup.js` `ui.js` `figure.js` `charts.js` `reminder.js` `views/`）、`icons/`、`media/`、`docs/` |
| ローカル確認 | 任意の静的サーバーでフォルダを配信（`file://` では Service Worker が動かない）。詳細は `README.md` |

## 10. 既知の制約・対象外

- アプリを閉じている間に、決まった時刻で通知を出すこと（Webの仕様上不可）。→ カレンダー登録で代替
- 端末間のデータ同期、アカウント機能（現時点では対象外）
- 自分で追加した写真・動画のバックアップ（現時点では対象外）
- 体操の実写の写真・動画は同梱していない（運営者が撮影して `media/` に追加できる）
- スマホ実機（通知の許可、共有シート、ホーム画面追加）での動作確認は、公開後に運営者が実施する

## 11. 今後の検討

- 運営者撮影の動画・写真の同梱（体操ごと）
- クラウド同期（機種変更・複数端末への対応。Supabase等。ログインと個人情報の取り扱いの設計が必要）。利用者から「機種変更で消えた」などの声があった場合に検討する
- 利用状況に応じた体操・ルーティンの追加（部位・症状別）
